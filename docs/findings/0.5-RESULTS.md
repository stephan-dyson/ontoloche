# Phase 0.5 — results

**Run 2026-08-28.** Ground truth was [pre-registered and committed](0.5-ground-truth-PREREGISTERED.md) as `093f102` **before** any proposal was generated.

**Method:** four agents, four model tiers, each given `sample_state.csv` (400 contiguous Montana rows from the CMS citations file) and a neutral task — "produce your best understanding of what this file describes, for a non-technical domain expert to confirm or correct." **No agent was told traps existed, what to look for, or that this was a test.** Each worked blind and independently.

**Scoring:** every checkable claim each agent made was verified mechanically against the data, or externally against CMS documentation. Numbers below are counted, not impressions.

## The result that matters most

**Haiku inverted the severity scale.** It reported:

> *"Scope Severity Code (B, C, D, E, F, G, J — **higher letters appear less serious**, D is most common with 235 cases)"*

**This is backwards.** CMS's scope-and-severity grid runs A (least serious) to L (most serious); **J, K and L are Immediate Jeopardy** — the categories that trigger civil money penalties and immediate remedies. Sources: [CMS QSO-23-01](https://www.cms.gov/files/document/qso-23-01-nh-revised-2026-01-28.pdf), [Wisconsin DHS scope-and-severity grid](https://www.dhs.wisconsin.gov/publications/p02055.pdf), [CMS SFF scoring methodology](https://www.cms.gov/Medicare/Provider-Enrollment-and-Certification/CertificationandComplianc/Downloads/SFFSCORINGMETHODOLOGY.pdf).

**Why this is the finding and not a curiosity.** Severity is *the* field that answers "which facilities are worst." An inverted reading turns a "most serious violations" report into a "least serious violations" report while every number in it stays correct. Nothing errors. Nothing looks wrong. **The user cannot detect it from the output** — only from domain knowledge they may not have, or from a source they were never pointed at.

Haiku's second error compounds it: it claimed *"some deficiency tags span multiple categories"* and cited tag `0600` as an example. **Counted: 0 of 92 tags span more than one category**, and `0600` appears under exactly one. A confident claim, a named example, and both wrong.

**This is Cause C from [finding 0.1](FINDINGS-0.1-tenshen-archaeology.md), reappearing in a completely different system**: the failure is not that something breaks, it is that something *quietly does not work* while everything looks fine.

## The pre-registered prediction was half right

**Predicted:** structure largely correct, traps are where it fails, T2 the critical one.

**Correct on:** structure (4/4) and T2 being the discriminator (missed by 2 of 4).

**Wrong on:** I predicted T2 might be missed by *everyone*. It was caught by both top-tier runs — and caught *well*:

- **B (Sonnet)** found all 6 rows, observed all 6 carry status `Past Non-Compliance`, proposed a domain explanation (a violation already fixed before a later survey cited it), and **asked the user to confirm rather than asserting it**. Verified: all 6 anomaly rows are indeed `Past Non-Compliance`.
- **A (Opus)** found the same 6, measured the worst at **108 days early** (verified: exactly 108), identified that both they and the 8 blank-correction-date rows *"will produce nonsense if fed into a days-to-correct average"*, and then **computed the metric correctly with them excluded**: median 29 days, middle half 22–37. Verified exactly: median 29.0, Q1 22, Q3 37, n=386.

**That is not trap-avoidance. That is the walkthrough's step 2 working as specified**, unprompted, on real government data.

## My ground truth was incomplete — the best agent beat it

Pre-registration listed seven traps. **A surfaced at least four more that are real and that I had not identified:**

1. **Survivorship bias.** *"Only problems are in here. Clean inspections are invisible."* A facility with a spotless survey does not appear at all, so citations-per-inspection computed from this file is systematically too high and absence looks like excellence. **This is the most serious analytical trap in the dataset and it was not in my ground truth.**
2. **Excel destroys the keys.** `CCN` and `ZIP Code` are digit strings; opening in Excel strips leading zeros and can merge facility identities. For a user whose primary tool *is* Excel, this is the difference between a working analysis and a corrupted one.
3. **The time window is uneven per facility.** Cycles run on different clocks, so cross-facility trend lines mostly measure inspection *frequency*, not care quality.
4. **Five columns carry zero information** in this slice (`State`, `Survey Type`, `Deficiency Prefix`, `Infection Control`, `IIDR`) — verified, all single-valued.

A also modelled the file as **four** entities rather than three, promoting the deficiency tag to a first-class regulation entity with the description as *its* property. Against my three-level ground truth that reads as a deviation; **it is better than my ground truth**, and it is precisely the "capability predicate vs entity" distinction finding 0.1 said the registry must be able to hold.

**Recorded as a limitation of the test, not a bonus for the agent:** a ground truth authored by one party and beaten by a subject is weak evidence in *both* directions. It means the 7-trap score understates all four agents, and it means my trap list should not be treated as complete.

## What this does and does not license

**Supports** — the walkthrough's step 2 is achievable *at the top model tier*. Two independent runs produced readings a domain expert could confirm or correct in a handful of decisions, with calibrated uncertainty, zero fabricated numbers, and unprompted discovery of real data-quality problems. **[Observed]**

**Does not support** — that this works cheaply. **The cheapest tier produced a confident, fluent, silently-inverted reading of the single most consequential field.** Cost per file is a live constraint for an ingest product, and this says the economics cannot be met by dropping model tier at this step. **[Observed]**

**Does not test at all:**
- **The correction rate a real user experiences.** I verified claims against data; I did not put these readings in front of a domain expert. Score 3 as pre-registered — *"claims a domain expert would have to correct, over total claims"* — **was not measured.** What was measured is factual accuracy, which is necessary but not sufficient: a reading can be entirely accurate and still be organised in a way an expert would restructure.
- **Whether a user keeps reviewing.** The rubber-stamping risk in `WALKTHROUGH.md` is untouched. That needs a human.
- **Entity resolution across name variants.** All 10 facilities in this file have clean 1:1 CCN↔name. The 104 shared names live elsewhere in the full file; **T4 was not fairly testable here.**
- **People.** No `Inspector` column exists, so step 4's action has no counterpart, as flagged before the run.

## Consequences for the plan

1. **Step 5 of the walkthrough is confirmed load-bearing, not decorative.** Two of four runs would have handed a user a silently wrong reading. The impact-analysis screen — *"here is what will not understand this"* — is the only proposed mechanism that catches a confident wrong answer, and this run is direct evidence it is needed.
2. **Model tier is a product parameter, not an implementation detail.** It belongs in the interface discussion and in any cost model. A cheap-tier proposal is not a degraded version of a good one; it is a *differently wrong* one, and the wrongness is invisible.
3. **Verification against an external authority must be part of the product, not the test harness.** The severity inversion was caught by checking CMS, not by inspecting data. A tool that maps domain data and never consults domain documentation will reproduce this failure class for every user.
4. **Phase 0.5 does not clear Phase 1 on its own.** It removes one specific fear (that proposals are hopeless) and replaces it with a sharper, narrower one (that proposals are confidently wrong at low cost, in ways only a domain expert or an external source can detect).
