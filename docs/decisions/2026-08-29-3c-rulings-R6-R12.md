# Rulings 2026-08-29 — the seven questions row 3c left (Q1–Q7 → R6–R12), and the kill-row trip

Supervisor rulings under the founder's make-assumptions directive. Source: [`docs/findings/3C-VALIDATION.md`](../findings/3C-VALIDATION.md) §6 — five decisions from the UC3 walk-through and two from the adversarial loop, each with a recommendation so a ruling is yes/no. The founder may reverse any of them; the two with product weight (R8, R12) are flagged.

**Sequencing principle applied throughout:** the founder's ordering rule is *unblock the Tenshen rebuild first*. Anything Tenshen's 2B needs goes to row 3d (in flight next). Type-to-type relations go to #4 EDGES. Surface additions that serve UC3/Phase 3 and governance but block nothing Tenshen needs go to a new row **3e — v0.1 amendments**, after EDGES. `v0` is labelled unstable precisely so that additive amendments are cheap; "wait for v1" is not required when the change is additive and default-off.

## R6 (Q1) — cross-namespace lookup in `resolve_type`: YES, additive, row 3e

`search_namespaces: Sequence[str] | None = None` on `resolve_type`; hits land in `alternatives` as `("<namespace>:<name>", score)`; `Resolution.complete` is `true` only when the caller named every namespace. No v0 caller changes. **Why not defer to v1:** scoping without lookup reintroduces mechanism 2 (re-propose what you cannot find) as the answer to mechanism 4 — UC3 is the kill-criterion fixture and this is its central finding. The Rule-K mitigation already taken (`scoped_to`, `why_incomplete`) stays.

## R7 (Q2) — `equivalent_to` between scoped types: YES, it is an EDGE — assigned to #4 EDGES.md

Accepted as stated: a relation between two scoped types is a type-to-type edge, so **EDGES v0 must carry type-level edges, not only instance-level ones**; `equivalent_to` is its first named family (symmetric, non-merging, provenance-bearing). A field on `TypeEntry` is rejected for the reason given. Added to the #4 brief.

## R8 (Q3) — value-level consumer gates: NEITHER option in v0; the warning IS taken (row 3d). *Founder-visible.*

`consumers()` warns when `gate` names no registered predicate, so `would_drop` is never read as a fact about a live gate. Option (1), `gate_values`, is deferred to Phase 3's decision — it makes the registry know what a *value* is, which INTERFACE §2.1 refuses on purpose; that refusal is a product boundary and the founder should see it before it moves. Option (2) is rejected (it deletes mechanism-C visibility, C11-02).

## R9 (Q4) — resolver-dependent tests non-binding for foreign resolvers: CONFIRMED as applied

The applied fix (skip keyed on the resolver being replaced, `resolver_factory` / `--resolver`, reference backends still run all three) is confirmed. Widening `_PROJECTION_FAMILIES` to coordinates stays forbidden — fitting the table to the second dataset. Moving domain-semantic judgement fully behind `Resolver` is a v1 item, recorded.

## R10 (Q5) — attribute schemas keyed per name as an override: YES, row 3e

`(namespace, kind, name)` schemas shadow the per-kind schema. It changes `oo_attr_schema`'s key; §9.4 already permits dropping a v0 store, so the migration is a drop-and-recreate with a version bump. Not v1 — it is the pollution the mechanism exists to prevent (§5.1), observed on CMS's own two value sets.

## R11 (Q6) — `reinstate`: YES, specify and implement, row 3e

`reinstate(type, reason, *, reinstated_by, namespace) -> TypeEntry | Refusal`, refusing when the retirement's `successor` is itself active (`successor_active` — sixteenth `Refusal.reason`, added to INTERFACE §5.12 in the same change per R3). A permanently burned word, retireable by one actor for everyone, is a governance defect in both UC1 (runtime classifier) and UC3 (dozens of publishers). The §5.9 justification correction already taken stands.

## R12 (Q7) — conformance for a multi-flag-degraded backend: the two-flag rule STANDS; a coverage report is REQUIRED, row 3d. *Founder-visible.*

No new non-negotiable flags. Every conformance run prints which contract ids it could not exercise and why (`CONFORMANCE` summary), and **a conformance claim without its coverage line is not a claim.** This is the same move as `ConsumerReport.complete=False`. It changes what "conformant" asserts — from "the whole suite passed" to "the whole suite passed; N ids not exercisable on this backend, listed" — which is the honest reading A5's gate needs. The founder should know that *"Tenshen conforms as a third backend"* is currently verified for one declined capability and assumed for the rest; 3d's natively-degraded leg (U2) plus this report closes that gap.

## The kill-row trip — recorded, judged not a stop

ROADMAP kill table: *"A capability predicate gets merged as a duplicate → Stop — this is the failure that destroys meaning."*

**What happened [Observed, commit `0e89037`, 3c round 9]:** on Tenshen's declared capability shape (`indexes_membership=False`), every predicate extent came back empty, two predicates with genuinely different members compared **equal**, the non-overridable `predicate_merge` refusal never fired, and the merge fell through to an overridable guard. Reproduced before being believed. Fixed: an extent that could not be computed is not a byte-identical extent (Rule U); the refusal is now non-overridable with a reason saying the extents were unknowable; C9-08 pins the compound shape.

**Judgment:** this is an implementation defect in the guard, caught by the adversarial loop before any real merge, on a fixture — not the *design* flattening a true distinction. The kill row exists for the latter. The row stays armed; the trip is evidence that it is the right row and that constraint 7's loop is load-bearing. **The founder may read it the other way** — that a guard which silently failed on the very backend it was written for is a design-level failure — and if so the stop is his to call. Recorded in the ROADMAP kill table with this commit.

## The kill-row trip — FOURTH instance (2026-08-29, row 4c, found by `check_merge_guard.py` itself)

**What happened [Observed, row 4c].** Not `merge_types`, and not `retire` either. Row #6 round 3's ruling was that *"the fix owed is a checker, not a fourth patch"*, and that row 4c's [`check_merge_guard.py`](../tools/check_merge_guard.py) must enumerate the **callers** as well as the four extent states. Its Part A does that from `registry.py`'s own AST — every function that writes a `successor` or an `aliases` onto a stored record, the two fields that change what a name resolves to — and it named one nobody had guarded on its first run: **`import_types`**.

The probe reproduced the collapse end to end against the shipped `Registry`:

1. `commentable` and `searchable` — two live predicates whose extents are non-empty and genuinely different (`{note}` and `{doc}`);
2. `merge_types` refuses that pair **non-overridably**, under every acknowledgement the call accepts;
3. `commentable` is retired — an ordinary, permitted governance act, **no successor**;
4. `import_types` writes `aliases: ["commentable"]` onto `searchable` with **no refusal, no warning and no acknowledgement**;
5. `resolve_type("commentable")` goes from `proposal / None / 0.4762` to **`existing / searchable / 1.0`** — a confidence `INTERFACE.md` §5.3 calls a registry **guarantee** — while the two extents stay different.

**Why `alias_collision` did not see it.** That guard refuses an alias that is a **live** entry's name, because §5.9b minted it to stop *two active entries holding one word between them*. A retired name is not a live entry — but **a retired predicate name still resolves, and a retired predicate still has an extent.** The guard was written for a *collision*; the failure is a *collapse*. Same write, different question.

**Fixed** by giving the alias write §5.10's identity guards #2 and #3, non-overridable, refused through `import_types`' existing `import_refused:<reason>` shape (it returns entries, not `Refusal`s). Pinned by **`C12-08`**, and by **`C12-09`** for the half a careless fix deletes: two predicates with non-empty *identical* extents may still be aliased, because `C10-09` narrowed the guard rather than closing the operation.

**A fifth instance of the same class, found beside it and fixed in the same commit.** `retire`'s overridable consumer guards ran *before* its non-overridable identity guards, so on `indexes_membership=False` a predicate retirement-with-successor was refused `no_consumer_evidence` — which advertises `force=True` — when the true answer was `predicate_merge`, which never moves. The outcome was safe; the story was wrong, and the story is what a caller acts on. Row 3c fixed the identical defect in `merge_types` (moving `cannot_record_override` after the four non-overridable refusals) and the lesson had not been carried across. Pinned by **`C9-19`**.

**Supervisor judgment, restated.** The diagnosis widens a third time and this is its full form: **a guard written for ONE CALL, over a fact that MORE THAN ONE CALL can change, reached through MORE THAN ONE FIELD.** `successor` and `aliases` both re-point what a name resolves to; three calls write them. The design is still not what tripped — `namespace` is untouched across all four, and `cross_namespace_merge` still refuses on live NYC data.

**What is different about the fourth trip, and it is the whole argument for continuing:** the three before it were found by human adversarial reviewers, one round at a time, each after the fix for the last one shipped. **This one was found by a checker, before any reviewer read the row, and that checker now runs inside the contract suite on every commit** — Part A fails on a caller it has never heard of, whether that caller is guarded or not, so the *next* one cannot arrive unnoticed. That is precisely what the third trip's ruling asked for, and it is the first time this class has had a mechanical gate. The stop option remains the founder's.

**Supervisor countersignature (2026-08-29 20:25, commit `8e641e6`).** The fourth-trip record and the judgment paragraph above were drafted by row 4c's worker in this file; the supervisor read them against the commit and concurs without amendment. ## The kill-row trip — FIFTH instance (2026-08-29, row 4c's first adversarial round)

**What happened [Observed, row 4c].** `_extent` read **one page** of a predicate's members and returned it. Every guard that compares two extents — `merge_types`' refusal #2, `retire(successor=)`'s (added by the third trip) and `_alias_identity_breach`'s (added by the fourth) — took `set(self._extent(...)[0])` and **threw away the third element**, which is the `why` saying the read was partial. So **two predicates whose FIRST PAGE of members happened to match compared equal**, and all three callers performed the collapse the same store refuses non-overridably when it is not paging.

Reproduced end to end against the shipped `Registry` on `DegradedAdapter(page_cap=2, page_cursor=True)` — this repository's own honest-paging double, added by row 3e's third round with the note that *"PACKAGE.md §3.3 permits it and UC3's scale produces it"*. True extents `{aaa_doc, bbb_note, zzz_draft}` and `{aaa_doc, bbb_note}`: `merge_types` returned a `MergeResult`, and `resolve_type("commentable")` answered `searchable` at confidence 1.0.

**This is Rule U's third operand on one expression.** Row 3c closed *unknowable is not equal*. Row #6's second round closed *empty is not equal*. **Nobody had closed *partial is not equal*** — and the read path had been publishing exactly that fact, as `PredicateEntry.why_extent_incomplete`, since row 3c. The guards discarded the one signal the read emits.

**Fixed on two axes, because there are two backends and one fix does not cover the other:**

| the backend | what it is | the defence |
|---|---|---|
| an honest **page** — `complete=False` **with** a cursor | there IS a rest | `_extent` loops to exhaustion |
| a **truncated** answer — `complete=False`, **no** cursor, or a page it cannot count, or a cursor it repeats | there is no rest to read | the guards fold `_extent`'s `why` into `knowable` |

Pinned by **`C10-11`** on both, on all three callers, plus the narrowing case (a genuine duplicate read across two pages still merges). `check_merge_guard.py` gains a `partial` and a `truncated` state for every collapsing caller — **its three real legs all answer in one page, which is precisely why it exited 0 while this was live**, and that gap is now closed by two synthetic rows rather than by hoping a future leg pages.

**Supervisor judgment.** The shape of the diagnosis does not change; its reach does. After five trips it reads: **one guard, one expression, three operands (unknowable / empty / partial), three callers (`merge_types`, `retire`, `import_types`), two fields (`successor`, `aliases`).** The design is still not what tripped — `namespace` is untouched across all five and `cross_namespace_merge` still refuses on live NYC data.

**What the fifth trip says about the fourth's argument.** Row 4c argued that the checker was the answer because it found the fourth trip mechanically. The fifth trip qualifies that honestly: **the checker exited 0 while this was live**, because its legs do not page. A checker only asks the questions its fixtures can pose, and the adversarial loop is what found the question it was not asking. Both are load-bearing and neither replaces the other — which is the strongest available argument for keeping constraint 7's loop, and against reading the fourth trip as evidence that reviewers are now optional.
