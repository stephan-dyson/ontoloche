## R79 — Q81: the flat-form constraint binds where the namespace is WRITTEN, as a warning first and a refusal one row later

**The question.** `C19-82` refuses a supplied `InputRef` whose identity segments carry `:` or `#`
at both invocation doors, but `INTERFACE.md` §2 types `namespace` as an unconstrained `str` and
every declaration door accepts `org:beacon`. A deployment can register types, edge families and
action families in such a namespace and never invoke a single action, with nothing warning it
at the door it actually used. **[Observed]** by round 2's fix-auditor; the `why` half was taken in
round 3 (`C19-90`), the binding half was not, because it changes a shipped type.

**Ruling.** *The constraint is a property of the word, not of the call that first tripped on it,
so it binds at the doors that write the word.* But the worker's default names the real cost —
*a namespace constraint added late breaks stored rows that are legal today* — and that cost is
the reason it is **two steps and not one**:

1. **Warning first.** `propose_type`, `approve` (via `_write_approved`) and `import_types` return
   `namespace_not_flat` (a new §5.4 value, its row per **R3**) when the namespace carries `:` or
   `#`, and still write. Every stored row that is legal today stays legal; every new one that
   will fail at an invocation door is told so at the door it knocked on. `C19-82`'s refusal is
   unchanged.
2. **Refusal one row later**, only after the warning has been live for a row and the
   `capability`-style evidence question — *did any reference backend or the design partner's
   harness ever write one?* — has an answer. If nobody did, the refusal lands with a migration
   note; if somebody did, the founder rules on the stored rows before anything refuses.

**Row:** the identity-surface row, item 1. **Why not the invocation doors, as the default says:**
the asymmetry the default would record in `PACKAGE.md` §7.3 is the one `INTERFACE.md` §2.3 calls
Cause B — one word, `namespace`, meaning a different thing at two doors — and this register does
not record a Cause B as a convention when it can close it. **[Inferred]** that no reference backend
writes a `:` namespace today; the warning step exists so that inference is tested before the
refusal is.

## R80 — Q82: a guard's escape may not depend on page order, and an unconstructable state is pinned as a test, not carried as a suspicion

**The question.** `merge_types`' `C10-20` guard escapes on `not same_word(holder, left.name)`,
and `_alias_clash` returns only the **first** active holder in page order — so a genuine third
live holder of one of `left.aliases` that sorts *after* a row spelling `left.name` would be
swallowed. **[Inferred]**: round 3's lens could not construct the prerequisite state because every
door that would create the second live holder already refuses. It is the only unconstructed
claim the row carries forward.

**Ruling, in two halves.**

1. **The escape is wrong regardless of whether the state is reachable**, because it makes a
   non-overridable identity guard's answer a function of sort order — the class R58 named for
   paging (*a guard never reads a page*) and the twelfth countersignature named for writes (*the
   write must be idempotent in the state the guard read*). Fix: `merge_types` excludes
   `left.name`'s spellings from the words it asks about **before** calling `_alias_clash`, so the
   holder that comes back is never one the guard would excuse. That is a change to what an
   identity guard reads and is argued against the fourteen records first (R53's boundary, lifted
   for this door by this ruling and no further).
2. **The unconstructable state is pinned, not carried.** The register does not hold a kill-row
   escape on an inference — the worker is right — and the way to discharge one the lenses cannot
   construct is a test that *proves the doors refuse the construction*: every door that could
   create a second live holder of one word, driven on every leg, each refusing by name. If that
   test ever goes green on a new door, the suspicion becomes a trip with its construction
   already written. **[Assumed]** that the construction is in fact impossible today; the test is
   what turns the assumption into an observation.

**Row:** the identity-surface row, item 2, and it goes **first** in that row's kill-row lens, as
the worker's default asks.

## R81 — Q83: no fourth round; the cap stands, and the row that pays its rounds to the identity surface on purpose replaces it

**The question.** Constraint 7's cap is three; rounds found 13, 12, 12 and each produced a trip.
Is three still the right number for a row whose every round found a trip?

**Ruling.** *The cap stands and round 4 does not run on row 6c.* The row is landed under the
*three rounds plus an honest convergence note* branch, which is the constraint as written, and
§6.7 is honest. What changes is **where the next rounds are spent, not how many there are**: two
consecutive trips in doors the row never touched mean the loop is now finding the identity
surface's own defects rather than the row's regressions, and those are cheaper to find in a row
with no diff of its own. **Constraint 7 gains one clause**: *when every round of a row's loop
produced a kill-row trip, the row's §6.7 predictions become round 1's brief for the next row that
touches an identity door* — for row 6c that is the identity-surface row, whose brief opens with
§6.7's four predictions and the R80 construction. **Supervisor's ruling; the founder may raise
the cap instead, and the counterweight is that 6c's three rounds cost a day and a half each.**

## R82 — Q84: the cost of `word_previously_retired` is the host's, it is §5.9's own price, and the read side that would make it visible is the founder's (Q80)

**The question.** The fourteenth trip's fix makes a word a tombstone holds as an alias
**permanently unusable in v0**, as a retired name already is; and unlike a retired name, a
caller cannot see the word is spoken for without resolving it first.

**Ruling.** *Recorded as §5.9's rule applied at one more field, and the price is paid by the host
that gave the word away as an alias and then retired the row that held it.* That is the same
host act, twice, and the registry's job is to make its consequence visible, not to reverse it —
a tombstone that could be raided for its aliases is the fourteenth trip. **No change in v0.** The
visibility gap is real and it is exactly **Q80** (`list_types(predicate=<transferred alias>)`
answers a confident zero), which is the founder's under the *one resolution call* principle; R82
adds one sentence to that question: *whatever Q80 rules for `list_types` also decides whether a
word a tombstone still answers to is visible before a caller tries to mint it.* Q80 and Q84 are
one question and the register keeps one number for it — **Q84 is closed into Q80.**
**[Observed]** that `resolve_type` already reports the holder at confidence 1.0, so the word is
never silently unavailable; it is unavailable with its reason on the first call that asks.
